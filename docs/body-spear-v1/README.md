# Arm spear / body-spear v1

V on keyboard or R3 on gamepad starts the existing committed chest finisher. A close ordinary zombie must be injured and recently staggered; the player needs both arms and sufficient energy. The readiness prompt reads **SPEAR THE BODY**. Body shots can open the brief stagger window. The sequence braces the victim, drives a straight spear hand through the torso, holds the contact, withdraws the hand/heart, releases the body and recovers the weapon.

This pass adapts the bracing, straight arm drive, held penetration and heavy withdrawal observed in the user's [fight reference](https://www.youtube.com/watch?v=DqAagh50JaI). Motion and anatomy are authored locally. No footage is included or redistributed, and this is one playable sequence, rather than a claim to reproduce every scene in the fight.

## Motion and anatomy

Headless Blender 2.93 exports 23 bone rotation tracks and a hip translation for each delivered body: ash witness, drowned dockworker, fever runner and crooked crawler. Each has its own bind basis and constrained limb lengths. The editable master is `.art-source/body-spear-v1/Body_Spear_v1.blend`; `CTRL_*` curves use seconds at 60 fps. `assets/animations/body-spear-v1.js` supplies the runtime overlay. Runtime and build require no Blender installation.

The windup draws a low crawler into a supported, reachable grapple before impact. Each source rig has its own bind basis. The editable `CTRL_arm_react` curve restrains the victim's arm resistance and drop: full inward rotation stretched the scanned sleeve/coat seams into long strips in the initial gameplay review. Its arm delta is applied relative to the current animated pose, so a restrained reaction does not replace lowered arms with the source bind pose. The revised bake is checked against the actual animated source skin's triangle edges. The paired first-person and co-op arms solve against the same fitted chest frame, retain their imported segment lengths and orient the measured finger axis along the penetration direction. The animated peer can take a bounded presentation step of up to 18 cm to preserve reach; it does not stretch its arms. Guest arm placement resolves terrain and stair support in the receiving world. The flat spear grip changes to the existing organ/weapon grips during withdrawal and recovery. Existing fused finger geometry has weighted support joints; it does not have separate independent digits.

`assets/models/body-spear-anatomy-v1.glb` contains an open entry rim, a larger exit rim and a hollow tunnel. It uses the project's original packed tissue atlas, with fascia, vessels, fractured rib ends and corrective compression/tension shapes. Entry and exit intersect the actual posed character skin; depth is not a guessed constant from one zombie. The source skin's colour, depth and distance hooks share both wound planes and the continuous bore, clearing folded interior coat surfaces. Wounded skins receive fresh owned materials so native WebGPU's already-converted ordinary material cannot retain an uncut node graph; release restores the exact originals. Gore-off rendering hides the wounds without changing damage, timing, AI or movement. The existing 48-droplet pool carries a 20-drop entry burst and 14-drop directed exit spray.

Native WebGPU cut inputs use the final skinned world position and interpolated membership attribute directly. The mask does not install a custom position override or capture bind-pose coordinates. Cut uniforms use Three's current-material reference nodes: identical programs can reuse loading preparation while every draw reads its own actor's wound values. The focused GPU checks include successive actors and all four body sources, so a cached template cannot silently leave their coats closed. Close wounded bodies also bound incident-light peaks to retain skin and clothing detail. Cloned graphic actor materials retain the source lighting parameters.

The host owns the existing 1.5-second sequence: impact at 0.24 s, extraction at 0.68 s and body/organ release at 0.95 s. Guest prediction cannot apply damage or extraction. No new network event or paid provider generation is required. The four delivered character GLBs, their textures and ten clips remain byte-for-byte unchanged.

## Runtime profiling and remaining acceptance work

`tests/zombie-live-quality.mjs --profile-only` measures the ordinary RAF loop at 1280×720, then four animated bodies and first/repeated finishers. It records render CPU time, animation, exact surface fitting, corpse physics, long tasks and the native adapter. It does not force simulation frames or synchronously wait for the GPU in the measured loop. `output/playwright/zombie-live-quality/profile-final.json` preserves the latest result. This desktop is shared with other running work; these measurements are specific to the current machine and load.

Corpse physics now uses sparse contact matrices and tests awake bodies against the complete static world. The previous dense table cleared roughly 1.2 million entries per step in the harbor. Candidate-pair tests cover native sphere/AABB modes, kinematic bodies, sleepers and filters; dense/sparse solver replay compares actual positions, velocities and contact events. World supports and the constrained Cannon solver are retained. The source surface fit also reuses typed vertex storage and scratch vectors while testing the actual posed triangles. Loading preparation uploads the real cut skins and wound kit, then restores original materials, geometry, visibility and culling.

The current profile passes without console errors, but the first-use finisher still hitches and the measured frame-time target is not met. Material program reuse alone has not removed cold surface fitting, actor binding and ragdoll preparation costs. Do not describe this as a stable 60 fps or film-quality result. The existing coarse source surfaces and fused fingers also limit anatomical detail.

`tests/zombie-rtc-probe.mjs` passes a real local PeerJS/WebRTC data-channel exchange. It does not start a game. The full public room-code co-op harness uses real host simulation and guest input/snapshots, and inspects native visuals sequentially to limit GPU contention. Earlier attempts stalled during arena startup; the passing serialized guest-render receipt above does not establish a passing live combat session. Consult `verification.json` for the latest distinct transport, gameplay and performance outcomes.

## Rebuild authoring

Run `blender.exe --background --python scripts/author-body-spear-v1.py` to rebuild the authored master and wound kit. After editing and saving the master curves, append `-- --export-only` to rebake motion without reconstructing the master. To regenerate the offline study, set `BODY_SPEAR_EVIDENCE=1`, run `node --test tests/body-spear-parity.test.mjs`, then run `blender.exe --background --python scripts/render-body-spear-v1.py`. The compressed posed-skin snapshot is temporary and can be removed after the study is saved. `node build.mjs` packages runtime files and bundled assets; it excludes `.art-source`, docs, tests and credentials.
