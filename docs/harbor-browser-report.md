# Harbor browser verification

Harness: `tests/harbor-browser.mjs`. Runtime results and screenshots are written to `output/playwright/harbor/`. Run using `PLAYWRIGHT_PATH=C:/Users/wolfk/Desktop/Dogfight/node_modules/playwright node tests/harbor-browser.mjs`; `DEAD_ARRIVAL_URL` and `HARBOR_QA_OUTPUT` can override the source URL and output directory.

The harness creates its own Chromium process and leaves the user's game tab intact. It starts through the real Harbor menu action and waits for the world asset promises. It then removes enemies and sets approach positions near loot/vehicle. Real movement input performs pickups; real backpack controls equip melee; real Q/W/Space input enters, drives, brakes and exits. This fixture verifies system integration, not encounter balance or an unassisted complete expedition.

Checks cover retained weapon ownership, pickup mesh removal, collision-safe vehicle exit, weapon hiding while driving, animated water, varied nonblank canvas, three inventory viewport layouts, console/page/HTTP errors and renderer/audio diagnostics. Unit tests separately cover collision and ownership edge cases.

Reference ledger: read QA skill `references/qa-release-checklists.md`, `checklists/visual-verification.md` and `checklists/playtest-qa.md`. UI reference ledger is in `docs/harbor-inventory.md`. Production deployment and physical mobile hardware are outside this harness.
